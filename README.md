# Geometry data

Files use `ssi-<operand-a>-<operand-b>-caseNN.json` names such as `ssi-cylinder-torus-case01.json`; pair names preserve operand order and case numbers are stable within each ordered pair. Each file in `Intersection/Geom_Intersect/SSI/Torus/` describes two ordered operands: `operands[0]` is A and `operands[1]` is B. Values are decimal strings rounded to the shortest representation that parses back to the same IEEE-754 binary64 value. The string `"-0"` preserves negative zero.

Torus entries store their center, X/Y/Z axes, major radius, and minor radius. Cylinder and sphere entries store a center, axes, and radius; cone entries also store the semi-angle. Planes store location, normal, X direction, and whether that direction is present. The files contain geometry only; test settings, source links, and run results are kept outside this repository.

STEP exchange models are stored as byte-preserved inputs under `step/`, `Classification/`, and `BooleanOperation/`. The classification and Boolean validation inputs are cataloged in the parent repository at `Tests/Kernel/_support/geometry-dataset-catalog-20261029.json`; that file records source paths, hashes, file sizes, overlapping case references, and source-scoped validation states. Repeated file contents are stored once by SHA-256. Classification inputs that failed the recorded BRep validity check are retained and marked in that external map; copying a STEP file does not certify its topology.

The two short-edge fixtures under `step/` were copied from the VARANIX test fixture inventory; their source and destination SHA-256 hashes are recorded in the parent repository's validation note. Their Part 21 envelope markers are present, but parser and topology validation have not been run for this dataset publication.
